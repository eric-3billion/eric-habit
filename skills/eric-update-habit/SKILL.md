# eric-update-habit — 세션 마이닝으로 habits 갱신

Claude 와 주고받은 교정 핑퐁 중 **아직 `habits/` 에 없는 습관**을 찾아 SSOT 에 반영한다. 이 문서는 *마이닝 절차*만 담는다.

핵심: **찾는 건 쉽고 걸러내는 게 어렵다.** 세션에서 사용자가 교정한 것의 대부분은 **이미 기록된 룰의 재발화**다. 이 스킬의 가치는 "많이 찾기"가 아니라 **재발화·환각·일회성 취향을 걷어내고 남는 잔여물**을 건지는 것이다.

> **여기선 서브에이전트를 쓴다 — eric-review 와 반대다.** eric-review 는 메인 루프가 직접 하도록 못박았지만(거긴 대상이 PR 한 개, 서브에이전트가 스냅샷을 못 읽어 깨졌다), 여기 대상은 **수백 KB~수 MB 의 트랜스크립트**라 메인 컨텍스트에 올릴 수도 없고 올릴 이유도 없다. 마이너는 조각을 읽고 **후보만** 반환한다. 두 스킬을 "통일"하지 말 것.

## 절차

1. **대상 세션 확정** — `$ARGUMENTS` 의 주제 키워드(예: `billing`)·프로젝트 경로·기간. 없으면 최근 작업 프로젝트로 물어본다.
   ```bash
   # 후보 나열: 키워드 언급 수 · 크기 · 날짜
   for f in ~/.claude/projects/<프로젝트>/*.jsonl; do
     c=$(grep -ci "<키워드>" "$f"); [ "${c:-0}" -gt 50 ] && echo "$c $(stat -f '%z %Sm' -t '%Y-%m-%d' "$f") $f"
   done | sort -rn
   ```

2. **resume 체인 중복 제거** (가장 큰 절약):
   > **왜** — `--resume`/`--continue` 로 이어간 세션은 새 파일로 저장되면서 **이전 대화를 통째로 안고 간다.** 실측: billing 세션 8개(총 380MB)가 전부 가장 큰 파일 하나의 부분집합이었다. 모르고 8개를 다 돌리면 같은 발화를 4~8번 마이닝한다.
   - 가장 큰 파일을 기준으로, 나머지 각각에서 **긴 줄 15개를 무작위 표집**해 기준 파일에 그대로 들어 있는지 본다(`in` 문자열 포함 검사). 15/15 면 부분집합으로 보고 **버린다.**
   - 남은 파일이 여럿이면 각각 독립 세션이니 전부 대상.
   - **첫 사용자 발화가 같으면 같은 체인**이다 — 크기·날짜만 보지 말고 이걸로 먼저 묶으면 표집 검사를 아낀다.

   **증분 — 이미 마이닝한 체인이 이어졌을 때**: 같은 체인을 나중에 다시 돌리면 **이전에 마이닝한 구간을 통째로 재마이닝**하게 된다(체인은 계속 자란다). 직전 추출본이 남아 있으면 **문단 단위 차집합으로 델타만** 뽑아 그것만 마이닝한다.
   ```python
   seen = set(old_extract.split("\n\n"))
   delta = "\n\n".join(p for p in new_extract.split("\n\n") if p not in seen)
   ```
   - 단순 접두어 절단(`new[len(old):]`)은 **쓰지 마라** — 재개 시 압축·요약이 끼면 앞부분이 그대로 보존되지 않아 접두어가 아니게 된다(실측). 문단 차집합이 안전하다.
   - 델타가 작으면(수십 KB) 조각을 나누는 대신 **같은 전체 자료를 2개 마이너가 독립적으로** 훑게 한다 — 조각을 쪼개면 "2회 이상 반복" 문턱을 각자 못 보고, 둘의 합의가 곧 교차 신뢰도가 된다.
   - **직전 마이닝에서 방금 추가한 룰 목록을 마이너에게 명시**한다. habits 파일을 읽게 해도, 갓 넣은 룰은 그 세션 대화에 그대로 남아 있어 "새 발견"으로 다시 올라오기 쉽다.

3. **사용자 발화만 추출** — 트랜스크립트의 99%는 도구 출력·어시스턴트 응답이다. 마이닝 대상은 **사용자가 친 말**뿐:
   ```bash
   jq -r 'select(.type=="user" and (.isMeta|not)) | .message.content
          | if type=="string" then . elif type=="array" then (map(select(.type=="text")|.text)|join("\n")) else empty end
          | select(length>0)' "$SESSION.jsonl" \
     | grep -v '^<command-\|^<local-command\|^Caveat:\|^\[Request interrupted' \
     | awk 'BEGIN{RS="";ORS="\n\n"} !/^<system-reminder/' > user-speech.txt
   ```
   (슬래시 명령 stdout·system-reminder·인터럽트 마커는 사용자 발화가 아니다.)

4. **조각내기** — 메시지 경계(`\n\n`)에서 **조각당 ~120KB** 로. 조각 수 = 병렬 마이너 수(보통 3~5).

5. **병렬 마이닝** — 조각마다 서브에이전트 하나. 각 마이너에게 반드시 지시할 것:
   - **먼저 `habits/` 전체를 Read**(00~06 + canonical-examples + `cases/` 전부) 해 기존 룰을 파악.
   - 조각을 **끝까지** 읽고, 교정·지적·반복 요구 순간을 찾는다. 신호: "아니", "그게 아니라", "왜 ~냐", "싫어", "하지마", "무조건", "항상", "절대", 강한 어조, 같은 지적의 반복.
   - **채택 문턱**(하나는 만족): ① 세션 내 2회 이상 반복 ② "항상/무조건/절대" 류 명시적 규칙화 ③ 한 번이지만 결과물을 되돌릴 만큼 강한 교정.
   - 후보마다: `QUOTE`(원문 그대로 — 뒤에 grep 검증한다고 명시) · `CONTEXT` · `RULE` · **`EXISTING`(가장 가까운 기존 룰과 무엇이 다른지)** · `TARGET` · `CONFIDENCE`.
   > **`EXISTING` 칸이 이 스킬의 핵심 장치다.** 가장 흔한 실패는 이미 있는 룰을 새 발견으로 보고하는 것 — 마이너에게 "이 칸을 못 채우겠으면 그 후보는 버려라"라고 명시한다.

6. **인용 검증** (환각 컷) — 후보의 `QUOTE` 를 원본 추출본에서 `grep -F` 로 대조한다. **안 나오면 그 후보는 버린다** — 마이너가 요약·윤색한 것이고, 윤색된 인용 위에 룰을 세우면 사용자가 하지도 않은 말이 SSOT 에 박힌다.

7. **교차 정리 + 분류** — 조각 간 같은 취지는 병합. 남은 후보를 셋으로 나눈다:
   - **신규** — 기존 룰에 없는 축. 새 절 또는 새 파일.
   - **보강** — 기존 룰은 맞는데 **조건·예외·경계선**이 빠져 있음. 해당 절에 문장/예시 추가.
   - **정정** — 기존 룰이 실제 습관과 **어긋나거나, 뭉개서 오작동을 유발**. 가장 가치 높다 — 지금 SSOT 가 Claude 를 잘못 인도하고 있다는 뜻이니 **최우선으로 올린다.**
     > 실측 신호 셋: ① 기존 룰이 권장 목록에 올려둔 패턴을 사용자가 실제로는 싫어함(용도가 갈리는데 안 갈라놨음) ② 룰에 **상한선·경계 조건이 없어** 반대 방향으로 끌고 감 ③ 두 파일의 룰이 **한 사례에서 충돌**하는데 판별 기준이 없음(예: "도메인 룰은 순수함수로" vs "얕은 포장 금지"가 한 줄짜리에서). ④ "일반 상식이라 설명 생략"으로 뭉갠 항목이 실제로는 강한 교정 지점.

   - **교차 신뢰도**: 서로 다른 조각의 마이너가 **독립적으로 같은 룰**을 뽑았다면 세션 전반에 걸친 습관이라는 뜻 — 단일 조각 후보보다 훨씬 강하다. 몇 개 조각에서 나왔는지 후보마다 표시한다.
   - **후보가 10건을 넘으면 티어링한다** — 전건 상세 설명이 비현실적이고(실측: 52건 → 병합 34건), AskUserQuestion 도 최대 4질문 × 4옵션 = **16개까지만** 받는다. 티어: `정정` → `교차 2+조각` → `단일 high` → `low·문턱 근처`. **8번 상세 설명은 상위 티어부터 한 화면에 소화 가능한 만큼만**(보통 4~8건) 하고, 나머지는 한 줄 목록으로 보여준 뒤 사용자가 다음 티어를 요청하면 이어간다.
   - **코드 습관과 워크플로를 갈라 보고한다.** 마이닝에는 커밋 규율·조사 순서·문서 SSOT 같은 작업 방식이 대량으로 걸리는데, 이것들은 `habits/00~06`(코드 산출물 룰) 소관이 아니다 → 별도 파일(`07-workflow.md`) 또는 `~/.claude/rules/interaction.md` 로 제안하고, 섞어서 한 목록에 내놓지 않는다.

8. **후보 전건 상세 설명** (선택 UI 앞에 반드시 온다 — eric-review 8번과 같은 규율):
   후보마다 한 섹션씩, **번호·분류(신규/보강/정정)·대상 파일**을 달고:
   - **원문 인용** — 검증된 사용자 발화 그대로(맥락상 필요하면 여러 개).
   - **무슨 상황이었나** — 어떤 코드/제안에 대한 교정이었는지.
   - **함의하는 룰** — 한 문장으로.
   - **기존 habits 와의 관계** — 어느 파일 어느 절에 붙는지, 왜 재발화가 아닌지.
   - **반영 초안** — habits 하우스 스타일로 쓴 **실제 문단/예시**(아래 하우스 스타일). 사용자가 문구를 보고 판단해야 한다.
   - **반론 여지** — 일회성 취향일 가능성, 기존 룰과의 긴장, 표본 부족(rule of three) 등 솔직히.

9. **선택 UI** — **자동 반영 금지. 항상 사용자가 고른다.**
   - **AskUserQuestion**: 후보 1건 = 옵션 1개, `multiSelect: true`. `label`=`분류 — 제목`, `description`=`대상 파일`, `preview`=반영 초안 전문.
   - 질문당 4개 초과면 분류/파일별로 질문을 나눈다(최대 4질문).
   - 8번 직후 사용자가 **말로 골라버리면** AskUserQuestion 없이 그대로 진행한다.

10. **선택분만 반영** — 고른 후보만 habits 에 쓴다. 파일 배치 판단은 **종류가 아니라 변경 축**으로([02-structure-cohesion](../../habits/02-structure-cohesion.md) 수평 축) — "이 룰이 바뀌면 어느 파일만 고치면 되나".
    - 짧은 룰 → 기존 파일의 해당 절에 흡수. 새 축이면 새 절.
    - **배경 서사(헛다리 포함)가 길면 `cases/` 로 빼고** 본문에서는 한 줄로 링크. 이 레포 관행은 오답 경로도 남기는 것이다.
    - 실제 코드 패턴이면 `canonical-examples.md`.
    - 반영 후 관련 파일의 상호 링크(`→ 연관:`)도 갱신.

11. **마무리** — 반영한 것/버린 것(재발화·환각·문턱 미달을 각각 한 줄씩)을 보고하고 **커밋 메시지 초안**을 제시한다. **커밋·푸시는 사용자 지시가 있을 때만.**

## 하우스 스타일 (habits 에 쓸 때)

- 한국어 문어체(`~한다`). 스캔 가능한 불릿 + **굵게** 강조. 장황한 서술 금지.
- **❌/✅ 코드 쌍**으로 보여준다 — 말로만 된 룰은 잘 안 지켜진다.
- **도메인 중립으로 추상화한다.** 사내 코드를 그대로 싣지 말고 패턴만 남긴다(주문·카테고리·상품 등 중립 도메인으로 치환). `canonical-examples.md` 상단이 이미 이 원칙을 명시한다.
  > 환자 데이터·샘플 ID·PII·사내 식별자는 **절대** SSOT 에 들어가지 않는다. 인용에 섞여 있으면 그 부분을 추상화하거나 후보에서 뺀다.
- 룰마다 **왜**를 한 줄 — 근거 없는 금지는 다음 사람이 되돌린다.
- 관련 룰은 `[00-intent](00-intent.md)` 식으로 상호 링크.

## 하지 말 것

- 사용자 확인 없이 habits 수정 (SSOT 는 사용자 소유)
- 검증 실패한 인용으로 룰 세우기
- 재발화를 신규로 올리기 (`EXISTING` 미기재 후보는 버림)
- 일회성 취향을 룰로 승격 (문턱 미달은 보고만)
- 자동 커밋·푸시
- resume 체인 중복 제거 생략 (같은 발화를 N번 마이닝)
